# Оценка поиска по загруженным документам

`eval.managed_retrieval` оценивает поиск по зафиксированной копии базы знаний. Он
не вызывает LLM, Tavily или GigaChat. После сохранения снимка команда `run` не
читает текущую базу: замена или архивирование документов не меняет эксперимент.
Исторический `eval.compare_retrieval` по двум встроенным PDF остаётся отдельным.

Размеченного набора для новых пользовательских документов пока нет. Команда
`snapshot` создаёт **пустой шаблон разметки**, а не готовые вопросы и ответы.

## 1. Сохранить корпус

Сначала загрузите и обработайте документы в базе знаний. Из корня проекта:

```bash
uv run python -m eval.managed_retrieval snapshot \
  --output .cache/managed-eval/v1/snapshot.json \
  --labels .cache/managed-eval/v1/labels.jsonl \
  --model minilm-multi
```

Для части документов добавьте `--documents ID_1 ID_2`. По умолчанию берутся все
активные документы с доступным текстом. Снимок содержит точные фрагменты и входы
эмбеддера, версии документов, SHA-256 оригиналов, версию парсера и настройки
индекса. Он содержит текст документов; сохраните его вместе с разметкой в
подходящую постоянную папку, если планируете очищать `.cache`.

Для первого скачивания закреплённой embedding-модели разрешён отдельный флаг
`--allow-model-download`. Без этого флага используются только локальные файлы
модели с корректными контрольными суммами. Существующие файлы результатов и
снимков не перезаписываются.

## 2. Разметить вопросы вручную

В каждой строке `labels.jsonl` заполните `question` и `gold[].quote`: цитата
должна буквально присутствовать в соответствующем фрагменте снимка. Для
таблицы указывайте конкретное значение вместе с достаточным контекстом, а не
пересказ. `candidate_context` помогает выбрать цитату; сам по себе он не эталон.

Поля `document_id`, `version_id`, `block_id` и `locator` связывают эталон с
источником. Для встроенных старых чанков `block_id` может быть `null`; для DOCX
и Excel вместо выдуманной страницы используется локатор абзаца, таблицы или
листа. Если вопрос требует двух фактов, добавьте оба фрагмента в `gold`.

В шаблоне `document_ids` ограничивает поиск одним документом. Для проверки
поиска **по всей базе** задайте `"document_ids": null`. Область поиска сохраняется
в результате; сравнивать результаты разных областей как одинаковые нельзя.

Добавляйте независимые вопросы с `split: "dev"` и `split: "test"`. Переформулировки
одного вопроса должны иметь один `group` и один split. Настройки выбираются по
dev; test используется для контрольного замера. Не превращайте ответы агента
в эталон автоматически.

```bash
uv run python -m eval.managed_retrieval validate \
  --snapshot .cache/managed-eval/v1/snapshot.json \
  --labels .cache/managed-eval/v1/labels.jsonl
```

Пустая разметка, чужой SHA снимка, отсутствующая цитата, неверная версия,
локатор и пересечение групп между dev/test отклоняются до загрузки модели.

## 3. Сравнить модели на одном снимке

```bash
uv run python -m eval.managed_retrieval run \
  --snapshot .cache/managed-eval/v1/snapshot.json \
  --labels .cache/managed-eval/v1/labels.jsonl \
  --model minilm-multi --mode dense \
  --output .cache/managed-eval/v1/minilm-dense.json

uv run python -m eval.managed_retrieval run \
  --snapshot .cache/managed-eval/v1/snapshot.json \
  --labels .cache/managed-eval/v1/labels.jsonl \
  --model e5-small --mode dense \
  --output .cache/managed-eval/v1/e5-dense.json
```

`--mode hybrid` дополнительно проверяет BM25 + векторный поиск с RRF. Фрагменты
и тексты для векторизации остаются одинаковыми при смене модели. Поле
`passages_over_model_token_limit` показывает, сколько из них длиннее контекста
выбранного эмбеддера: его нельзя игнорировать при интерпретации сравнения.

| Метрика | Что показывает |
|---|---|
| hit@1 | Есть ли хотя бы один эталонный фрагмент на первом месте |
| hit@5 | Есть ли хотя бы один эталонный фрагмент среди первых пяти |
| MRR@10 | Насколько высоко найден первый эталон: `1 / позиция`, либо 0 |
| evidence_recall@5 | Какая доля всех нужных фрагментов найдена в первой пятёрке |
| all_evidence@5 | Найдены ли в первой пятёрке все нужные фрагменты вопроса |

Файл сохраняет отдельные сводки dev/test, ранжирование каждого вопроса, SHA
снимка и разметки, модель и настройки. Это оценка retrieval. Она не измеряет
достоверность итогового ответа, выбор инструментов агентом и ошибки OCR — для
них нужны отдельные проверки.

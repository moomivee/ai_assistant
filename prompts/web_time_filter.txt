В proposed одновременно заданы days и start_date/end_date. Эти способы задания периода взаимоисключающие. Выбери один вариант с учётом исходного question, previous, today и search_query:
- unbounded — убрать временное окно. Для «последнего события» без заданного пользователем периода это предпочтительный первый поиск: последнее событие могло быть давно. Актуальность нужно проверить по найденным публикациям, не выдумывать.
- relative — оставить предложенное days, убрать обе даты. Подходит для явно запрошенных последних N дней.
- dates — оставить предложенные start_date/end_date, убрать days. Подходит для явно заданного календарного периода.

Не снимай явно заданный пользователем временной период. Не выбирай даты только потому, что они выглядят точнее; опирайся на смысл вопроса. Значения фильтров приложение возьмёт из proposed, поэтому не генерируй новые числа и даты. Это выбор параметров поиска, а не ответ на отраслевой вопрос.

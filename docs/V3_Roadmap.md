## Что уже есть в основе

Ограниченный агентский цикл LangGraph: модель выбирает действия, приложение проверяет аргументы, выполняет инструменты через Ouroboros и возвращает наблюдения. Есть поиск по отчётам, чтение страницы PDF, Tavily, прогноз, structured output, трейсы и eval. Защита от повторов и бюджеты выполнения остаются.

В UI уже раскрывается текст источника и страница. Следующий шаг — привязка конкретного утверждения к точной цитате и месту в оригинале, включая другие форматы документов.

## 1. Понятные возможности на тестовом стенде

Сохранить ответ, инструменты, аргументы, источники и трейс. Добавить три раздела:

1. **Возможности** — компактные карточки задач, пример запроса, необходимые данные, ограничения.
2. **База знаний** — документы, загрузка, обработка, версии, первоисточники и обновления.
3. **Тестирование** — вопрос, ответ, доказательства, действия и показатели выполнения.

Карточки: «Найти факт в документе», «Сравнить показатели», «Проверить актуальное событие», «Сопоставить отчёт и веб», «Рассчитать прогноз». Кнопка примера только заполняет поле, запрос выполняется пользователем. Текущий прогноз поддерживает Brent/WTI/Urals; для Urals и сценариев нужны явные допущения.

Дополнительные варианты навигации: поиск по примерам, фильтры по типу задачи, быстрые действия возле документа («Задать вопрос по этому документу», «Сравнить с другим»). В первую итерацию достаточно карточек и выбора документа.

Доступность показывать по конфигурации: модель подключена, Tavily настроен, документ проиндексирован. Не обозначать планируемые возможности как уже работающие. Переключатель «Только база знаний» и выбор документов явно ограничивают контекст.

**Готово, когда:** новый пользователь видит, что можно спросить; примеры реально проходят; отключённый сервис имеет понятное объяснение. В трейсах показываются наблюдаемые действия и краткая цель, а не заявленный доступ к внутреннему рассуждению модели.

## 2. Управляемая база знаний и OCR

### Поддержка форматов

| Вход | Предлагаемая обработка | Адрес доказательства |
|---|---|---|
| Текстовый PDF | Извлечение текста, структуры, таблиц | Версия документа, физическая страница PDF, блок |
| Сканированный/смешанный PDF | OCR растровых страниц/областей | Страница, область при наличии, отметка OCR |
| PNG/JPEG | OCR текста и таблиц | Изображение, область |
| DOCX | Абзацы, заголовки, таблицы | Раздел, абзац или таблица |
| XLSX | Табличный адаптер с координатами | Лист и диапазон ячеек |
| CSV | Разбор кодировки, разделителя, колонок | Строки и колонки |

Первый кандидат: локальные Docling + Tesseract с русским и английским языками, openpyxl для точной адресации XLSX, стандартный CSV-парсер. Выбор подтвердить небольшим набором файлов и сборкой ARM64 Docker. Конкретные версии зависимостей фиксировать после проверки совместимости с текущим `uv.lock`.

Поддержка формата не гарантирует качество любого файла. Нечитаемые фото, сложные графики, рукопись, защищённые и повреждённые документы требуют явного результата «не обработан» или «нужна проверка». OCR текста на графике не означает извлечение точных чисел. Старый формат XLS не входит в первый этап.

В XLSX сохранять формулу и доступный сохранённый результат отдельно: openpyxl не пересчитывает формулы. При отсутствии результата нельзя подставлять выдуманное значение. Для DOCX не обещать стабильные номера страниц без зафиксированного PDF-представления.

### Жизненный цикл

Загрузка → проверка файла → извлечение/OCR → предварительный просмотр → чанки → эмбеддинги → публикация версии индекса.

- Оригинал, SHA-256, формат, издатель, название, дата документа и URL первоисточника.
- Дата загрузки отдельно от даты публикации; последняя может быть неизвестна.
- Версии документа, парсера/OCR, эмбеддера и индекса.
- Статусы: очередь, обработка, готов, частично обработан, ошибка.
- Просмотр извлечённого текста и таблиц; повторная обработка, архивирование.
- Повторная загрузка того же файла не размножает данные.
- Новый индекс публикуется целиком после завершения; текущие запросы используют согласованную версию.
- Архивированный документ исключается из новых поисков, но старые цитаты сохраняют адрес версии.

Для первого стенда достаточно файлового хранилища оригиналов, SQLite для каталога/заданий и существующего FAISS. Один фоновый обработчик документов отделяется от HTTP-запроса загрузки. Масштабирование на отдельную очередь/векторный сервер — по нагрузке, а не обязательная часть первого этапа.

Нормализованный блок содержит `document_id`, `version_id`, `block_id`, тип, текст, адрес и способ извлечения. Таблица сохраняет строки, колонки, объединения, заголовки и единицы; Markdown — представление для модели, не единственный источник истины.

Проверка MIME/расширения, ограничение размера/страниц, безопасные имена, отсутствие исполнения макросов. Содержимое документов рассматривается как данные, а не команды агенту. OCR выполняется локально; выбранные фрагменты будут передаваться облачному GigaChat, что должно быть видно в интерфейсе.

### Первоисточники и обновления

У каждого документа: «Оригинал», «Страница издателя», дата проверки и статус «ручное обновление / подключён адаптер / новая версия найдена».

Ссылка на конкретный PDF позволяет повторно скачать этот файл, но не обязательно обнаружить следующий выпуск. Для EIA и Банка России сначала проверить страницы публикаций и стабильность ссылок; затем добавить отдельные адаптеры обнаружения выпусков. Не угадывать новый URL заменой года.

Первый этап — кнопка «Проверить обновления». Автоматическая проверка по расписанию включается отдельно после проверки адаптера; новая версия проходит тот же ingestion. Сохранять историю, а не перезаписывать старый PDF. Даты и период прогноза Банка России не заменяют текущие котировки.

**Готово, когда:** каждый заявленный формат загружается через UI, прогресс виден, исходные координаты сохраняются, ошибки распознавания не скрываются, данные переживают перезапуск контейнера.

## 3. Доказательства рядом с утверждениями

Кликабельная ссылка [R1] или [W1] около утверждения раскрывает точную цитату, название, дату и переход к оригиналу.

- PDF: страница и фрагмент; подсветка области только при достоверных координатах.
- DOCX: раздел/абзац/таблица; XLSX: лист и диапазон; изображение: выделенная область.
- Веб: URL, цитата, время получения, доступная дата публикации; дата события хранится отдельно.
- Расчёт: данные и дата последнего наблюдения, метод, параметры, интервал и бэктест.

Модель выбирает существующие ID доказательств, а текст цитаты извлекает код из сохранённого источника. Сохраняются проверки смысла, единиц, полноты и чисел: совпадение цитаты само по себе не доказывает вывод. Ошибку OCR явно обозначать. Веб-сниппет отличать от извлечённого текста страницы.

**Готово, когда:** для каждого фактического утверждения можно открыть использованный фрагмент; подмена источника, неверная версия и отсутствующий ID выявляются тестами. В таблице проверяются значение + единица + строка + колонка.

## 4. RAG и объяснимая оценка

Текущий default — `minilm-multi`: `Xenova/paraphrase-multilingual-MiniLM-L12-v2`, ONNX, FAISS. Второй вариант — `Xenova/multilingual-e5-small`. Генеративный GigaChat и эмбеддер решают разные задачи; смена LLM не требует смены индекса.

Текущая нарезка — окна по 110 словам с перекрытием 28. У MiniLM в конфигурации лимит 128 токенов: измерить фактическое усечение текста и перейти к разбиению по токенам/структурным блокам после отдельного сравнения. Не утверждать заранее, что это единственная причина ошибок.

Показать в стенде: эмбеддер, версию корпуса, настройки чанков, top-k, найденные фрагменты и результаты eval.

| Метрика | Как читать |
|---|---|
| Hit@1 | Доля вопросов, у которых первый результат содержит эталонное доказательство |
| Hit@5 | Доля вопросов, у которых хотя бы один из пяти результатов содержит эталон |
| MRR@10 | Среднее 1/rank первого релевантного результата в top-10; если его нет — 0 |
| Evidence recall@5 | Доля всех необходимых независимых доказательств, найденных в top-5 |

Hit@5=0,8 означает 80% попаданий в этом наборе, а не 80% верных ответов агента. Для составного вопроса одного попадания может быть недостаточно. Cosine score не является вероятностью истинности и не сравнивается напрямую между эмбеддерами.

Сравнивать эмбеддеры на одинаковых корпусе, вопросах, разбиении и правилах релевантности. Разделять dev и test по группам фактов/документов. На расширенном корпусе добавить сканы, таблицы, русский/английский, несколько документов и вопросы без ответа. Часть эталонов проверить вручную; не превращать старые ошибки отладки в независимый test.

**Готово, когда:** воспроизводится таблица метрик с размером выборки, версиями, ошибками по вопросам и объяснением выбора. Качество OCR/парсинга, retrieval, выбора инструментов и ответа измеряется отдельно. Смена чанкинга — отдельный эксперимент от смены эмбеддера.

## 5. Развитие Tavily

Сохранить модельный выбор поиска с учётом приоритета отчётов. Политика «сначала RAG» не требует просматривать весь старый отчёт перед актуальным запросом.

- Разделить обнаружение источников (`web_search`) и чтение выбранной страницы (`read_web`, Tavily Extract).
- Дать модели тип запроса, период, глубину и допустимые фильтры в проверяемой схеме.
- Различать исторический вопрос, последнюю встречу и новости за период; не применять фиксированное окно 30 дней ко всем актуальным событиям.
- Показать запрос, применённые фильтры, причины отбрасывания и использованные цитаты.
- Дедупликация URL, кэш с датой получения, лимиты запросов и расходов.
- Доверенные домены и официальные первоисточники сохраняются; пустой результат не даёт права выдумывать факт или незаметно обходить ограничение «только отчёты».

Извлечение страниц может быть неполным. Сохранять статусы, не обещать доступ к любому сайту. URL проверяются до скачивания и после перенаправления; локальные адреса и служебные сети не доступны инструменту.

**Готово, когда:** агент различает актуальные и исторические события, при необходимости открывает найденную страницу, отдаёт проверяемую цитату и корректно сообщает об отсутствии результатов. Контролируемые фикстуры и живой Tavily оцениваются раздельно.

## 6. Больше возможностей Ouroboros

Оставить один управляющий цикл LangGraph; расширить использование уже закреплённого Ouroboros через адаптеры.

1. **Настоящие instruction skills.** Методики анализа отчётов, веб-исследования и прогноза. Использовать механизм манифестов/загрузки/каталога Ouroboros, а не только папку с текстами. В трейс записывать выбранный skill, версию и хеш. Учитывать enabled и допуск конкретного содержимого. Проверять выбор навыка на разных вопросах.
2. **Версионируемые исследовательские заметки.** Через `ouroboros.knowledge`: вопрос, документы и версии, доказательства, нерешённые вопросы. Заметка модели не становится рыночным первоисточником. Чтение/запись, просмотр и архивирование; изменение через `expected_revision`. Память изолируется по рабочему пространству.
3. **Провайдерский адаптер — отдельная оценка совместимости.** На текущем pin есть GigaChat transport, но `LLMClient.chat` игнорирует `response_format` в GigaChat lane. Для наших схем предпочтителен собственный тонкий адаптер нативного SDK, пока совместимость Ouroboros не подтверждена.

Не подключать второй полный runtime внутри LangGraph: у Ouroboros он сам управляет задачами, памятью, моделями и инструментами. Переход на него целиком потребовал бы отдельного сравнения архитектур. Самоизменение кода и автоматическое обучение не входят в этот этап.

**Готово, когда:** реальные API Ouroboros участвуют в загрузке навыков и работе заметок, это видно по трейсам и тестам; отключение навыка влияет на доступный контекст; старая заметка не подменяет свежий источник.

## 7. Облачный GigaChat

Сделать отдельный адаптер провайдера за общим интерфейсом структурированной генерации. Сохранить схемы Plan, NextAction, DraftAnswer/EvidenceAnswer и JudgeResult. Название конкретной модели выбрать из доступных в аккаунте и записывать в результаты.

Нативный GigaChat поддерживает JSON Schema, но его `response_format` отличается от OpenAI. Проверить enum, null, вложенные объекты, ограничения массивов и полный комплект наших схем. После ответа — Pydantic; ограниченная повторная попытка при необходимости и явный статус ошибки вместо правил, выдаваемых за ответ модели.

- Отдельные OAuth, обновление токена, timeout, 429, отказы и исчерпание квоты.
- Проверка TLS остаётся включённой, CA настраивается при необходимости.
- Параллелизм соответствует квоте аккаунта; расход токенов и время видны в трейсе.
- SDK фиксируется по проверенной стабильной версии; примеры из upstream main могут относиться к alpha.
- GigaChat становится основной моделью v3 после живой проверки. Qwen остаётся историческим baseline; молчаливого fallback на локальную модель нет.
- Облачная модель получает вопрос и выбранные фрагменты; полный файл автоматически в облако не загружается.

До реализации уточнить только способ доступа: прямой GigaChat API, корпоративный или Cloud.ru. Ключ пользователь добавляет локально в .env, не присылает в чат и не публикует в Git. Доступность моделей и условия подключения различаются; не обещать конкретный тариф заранее.

**Готово, когда:** авторизация, структурированные ответы, обработка ошибок и полный сценарий с реальным GigaChat прошли; результат сравнен с baseline на одинаковом корпусе. Замена модели сама по себе не доказывает улучшение.

| Этап | Результат | Контроль |
|---|---|---|
| 0 | Новая ветка и этот план | Основа точно совпадает со второй версией |

| 3 | OCR, DOCX/XLSX/CSV/изображения, просмотр и точные цитаты | Набор сложных файлов + таблицы + ресурсы ARM64 |

Каждый этап — отдельный коммит и короткий результат проверки. Новые известные ошибки добавляются в dev-регрессии. Финальное сравнение использует отложенные вопросы и ручной просмотр части ответов. Фиксировать код, промпты, модель, корпус, эмбеддер и датасет; не смешивать результаты разных версий.

Состояние этапов: 0 завершён; 1 — адаптер GigaChat подготовлен, живой smoke и карточки возможностей ожидаются; 2–6 — запланированы. Инструкция подключения: [GigaChat](GigaChat.md).

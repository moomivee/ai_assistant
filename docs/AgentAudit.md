# Аудит агентского цикла и eval

Проверка от 10 ноября 2026 года. Новая архитектура подготовлена в отдельной ветке. Прохождение тестов кода, выбор инструментов и правильность ответов рассматриваются отдельно.

Финализация документации — **11 ноября 2026 года**. Код исследованной версии зафиксирован на [c971a31](https://github.com/moomivee/ai_assistant/tree/c971a31c2076aaf348bca7a7c27eb6423863170a); новые результаты измерений при финализации не добавлялись. Краткая сводка для знакомства с проектом: [текущий результат и ограничения](Limitations.md).

Позднее добавлен [тестовый интерфейс с кратким трейсом](TestInterface.md). Он не меняет приведённые ниже измерения качества модели.

## Найденные причины

Прежняя реализация выбирала план в начале и проходила фиксированные узлы. Модель могла выбрать ветку, но не могла изменить следующий шаг после результата инструмента. Eval требовал точного совпадения вызовов и поощрял один маршрут вместо решения задачи.

Самопроверка той же Qwen оказалась ненадёжной: принимала неверную интерпретацию шкалы API и отклоняла правильный вывод. Копирование цитат, а затем адресация отдельных строк таблицы также приводили к потере пригодного ответа. Это наблюдения по реальным генерациям, а не предположение о слабости модели.

В отдельном диагностическом опыте Qwen 7B верно решила тот же вопрос свободным текстом и в структурированной схеме с предварительным кратким перечислением фактов. Добавление ещё одного определения API в контекст не помогло. В кандидате проверена схема «проверяемые наблюдения → утверждения со ссылками». Общий этап не содержит названий или характеристик конкретных сортов. Однако в полном проходе ошибка Urals/ESPO повторилась: успешный короткий опыт не считается доказательством исправления.

## Новая архитектура

- После каждого инструмента Qwen получает наблюдение и выбирает следующее действие. Можно уточнить поисковый запрос, открыть страницу PDF, обратиться к вебу или завершить работу.
- Новый `read_report` читает физическую страницу зарегистрированного отчёта. Поиск фрагмента и чтение страницы — разные действия.
- Допустимые действия ограничены JSON Schema и проверяются исполнителем. Сохранены приоритет отчётов, `report_only`, проверка параметров расчёта и бюджет из шести решений.
- Модель выбирает источники для ответа. Исходные блоки адресуются ID; их текст подставляется кодом. Числа и готовые ответы не записаны в генераторе.
- Проверка наличия цитируемых блоков и чисел обязательна. Самопроверка той же моделью доступна только как абляция `ANSWER_SELF_REVIEW=true`, по умолчанию отключена. Ни одна из этих проверок не гарантирует правильность смысла.
- `AGENT_MODE=loop` включает новый цикл; `AGENT_MODE=workflow` — сохранённую реализацию для сравнения.

Прогноз рассчитывает численный инструмент. Его числа и стандартные оговорки выводятся детерминированно; произвольный анализ документов формулирует LLM по источникам. [Полная схема и файлы](Architecture.md).

## Что проверяет eval

`tool_policy_pass` проверяет обязательные инструменты, запрещённые вызовы и RAG перед вебом. Дополнительное чтение страницы или поиск с другим запросом допустимы. Точное совпадение маршрута осталось диагностической метрикой. Если инструментов не требуется, ненужный вызов считается ошибкой.

Сбой одного запроса записывается в результат и остаётся в знаменателе. `response_contract_valid_rate` вычисляется по фактической валидации, а не присваивается автоматически. Без отдельной оценки содержания `task_success_rate=null`.

Для LLM-оценщика добавлены пять контрольных ответов: правильный, с переставленными значениями, с перевёрнутым смыслом API, пустой и нерелевантный. `eval.assess_saved` требует явно выбрать другую модель. Если она не проходит контроль, итоговый semantic success не публикуется. Другой размер Qwen тоже не обеспечивает полной независимости.

## Проверка зависимости от данных

`eval/counterfactual.py` дважды задаёт один вопрос о вымышленных сортах Orion и Vega. Во втором ответе инструмента значения меняются местами. Правильный вывод должен измениться. Третий случай сначала возвращает пустой поиск: проверяется, продолжит ли модель собирать данные и изменит ли запрос. Используется настоящая LLM, но источник синтетический: это проверка использования данных, а не качества retrieval или рыночных знаний.

Дополнительные десять вопросов находятся в `eval/data/audit.jsonl`: новые горизонты прогноза, недостающий дисконт, другие строки PDF, ложная предпосылка, отсутствующий документ, котировка и вопрос вне темы. Разметка подготовлена с участием AI, `human_review=pending`; это небольшой набор, не независимая статистическая оценка. После просмотра результатов он также становится материалом разработки.

## Retrieval: 320 поисковых запросов

40 вопросов × два эмбеддера × dense/hybrid × две формулировки. Документы, чанки и эталоны одинаковы. Hybrid использует BM25 и объединение рангов RRF.

| Эмбеддер | Поиск | Dev recall@5, clean query | Dev recall@5, полный вопрос |
|---|---|---:|---:|
| MiniLM multilingual | dense | 0.733 | 0.667 |
| MiniLM multilingual | hybrid | 0.667 | 0.600 |
| multilingual E5 small | dense | 0.467 | 0.400 |
| multilingual E5 small | hybrid | 0.400 | 0.333 |

В dev 15 вопросов, в test — 25. Выбор по dev сохранён: MiniLM + dense. Test используется для отчёта, не для выбора. Hybrid не улучшил dev и не включён по умолчанию. Абсолютные показатели показывают, что retrieval требует дальнейшей работы. Метрики используют точное совпадение нормализованной эталонной цитаты; в `read_report` иной layout таблицы может снизить такое совпадение даже при наличии нужных ячеек. Сравнение 320 поисковых запросов выполнено на одинаковом представлении чанков. [Ранжирования и все метрики](../eval/results/agent-audit-retrieval.json).

## Живые прогоны

Результаты содержания ниже получены при разборе ответов и первоисточников с участием AI. Независимая экспертная проверка ещё не проведена. Это небольшие диагностические наборы, а не оценка точности на будущих пользовательских вопросах.

| Проверка | Что получилось |
|---|---|
| Qwen 3B, три прежних dev-регрессии | Два прогноза корректны; для сравнения Urals/ESPO возвращён неполный ответ при найденной таблице: **2 из 3** |
| Qwen 7B, три прежних dev-регрессии | Два прогноза корректны; сравнение Urals/ESPO содержит ошибочный вывод о плотности: **2 из 3** |
| Qwen 7B, десять дополнительных вопросов | Правила инструментов: **9 из 10**; задача по рубрике с учётом содержания: **7 из 10** |
| Перестановка значений Orion/Vega | В обоих вариантах вывод соответствует данным: **2 из 2**; источник синтетический |
| Пустой первый поиск | **Не пройден**: модель повторяет запрос вместо новой формулировки |

В десяти дополнительных вопросах все ответы имели ожидаемый статус и корректную JSON-структуру. Это не обнаружило ошибки: лишнюю котировку в прогнозе WTI, неподтверждённые дополнения к ответу о Sokol и неверную интерпретацию API. Именно поэтому структурную валидацию нельзя считать метрикой качества ответа.

Для вопроса о добыче России модель выбрала `report_search → read_report` и нашла правильные показатели на полной странице. При этом четыре повторные попытки были отклонены. Котировка и отсутствие данных обработаны корректно, но также потребовали лишних шагов. Всего на десять вопросов понадобилось 49 LLM-вызовов; медиана времени на доступном Linux CPU составила 107 секунд. Это не измерение скорости на MacBook.

В тесте пустого поиска обнаружена и исправлена ошибка ограничителя: если единственная альтернатива — завершение, поиск с другой формулировкой теперь остаётся разрешён. Регрессионный тест кода подтверждает это. **Повторный живой прогон всё равно не прошёл:** Qwen 7B пять раз предложила исходную формулировку. Повторные вызовы инструмента не исполнялись, выдуманного ответа не появилось. Исправление harness не выдано за улучшение способности модели адаптироваться.

Полный набор 7B измерен до последнего исправления этого ограничения; после него отдельно повторён сценарий пустого поиска. Исходные результаты сохранены. Наличие 100 seed-вопросов не означает выполнение 100 end-to-end проверок. Полноценный Tavily-поиск и независимая экспертная оценка в этот прогон не входят.

## Калибровка оценщика

Qwen 3B как оценщик ответов 7B прошла только **2 из 5** контролей. Она дала максимальные баллы ответу с переставленными значениями, неверным направлением плотности и пустому описанию вместо сравнения. Оценивание остальных ответов поэтому не запускалось, `task_success_rate=null`. Такой результат не маскируется средним баллом.

## Проверки и воспроизводимость

**104 теста кода** проходят; Ruff не находит ошибок. Проверены ограничения цикла, восстановление допустимости нового запроса, чтение настоящего PDF, API и экспорт native Langfuse callbacks в локальный OTLP-приёмник. Тесты с заданными ответами модели проверяют код и не заменяют живые прогоны.

[Полные локальные трейсы](../eval/results/agent-audit-traces.jsonl.gz) содержат 7B, повтор сценария восстановления, 3B и калибровку. Это учебные вопросы и публичные источники. После скачивания:

```bash
gzip -dc eval/results/agent-audit-traces.jsonl.gz > /tmp/agent-audit-traces.jsonl
uv run python -m eval.traces candidates /tmp/agent-audit-traces.jsonl /tmp/agent-audit-candidates.jsonl
```

Кандидаты требуют разметки по первоисточнику. Синтетические сценарии следует отделять от реальных пользовательских вопросов. Сохранённые ответы и трейсы не переписываются после исправлений; версии различаются хешами кода и промптов. [Повторный расчёт маршрутных метрик](../eval/results/agent-audit-metrics-verification.json) проверяет, что последнее уточнение eval не изменило оценки уже сохранённых реальных ответов.

## Диагностические эксперименты

[Короткая проба формата ответа](../eval/results/agent-audit-answer-modes.json) дала правильный вывод при свободном тексте и при предварительном перечислении наблюдений. Однако полный проход со схемой подготовки ответа снова ошибся. [Дополнительное пояснение единиц](../eval/results/agent-audit-unit-reference.json) также не устранило сбой. Эти пробы не включены в итоговую метрику и не доказывают улучшение.

[Абляция самопроверки](../eval/results/agent-audit-self-review-ablation.json) показывает правильный черновик, отклонённый той же моделью, и неудачную попытку исправления. Поэтому самопроверка не является обязательным рабочим фильтром. [Вариант без подготовки наблюдений](../eval/results/agent-audit-before-preparation.json) также сохраняется: неверный вывод о плотности присутствовал и в нём.

Для старых синтетических прогонов содержимое набора сохранено непосредственно в `rows[].source`, а версия генератора входит в `code_sha256`. Поле `dataset_sha256` в этих ранних файлах ссылалось на контрольный файл judge; генератор исправлен для следующих запусков и теперь хеширует файл с самими синтетическими сценариями. Сохранённые исходные результаты не переписывались.

## Воспроизведение

При работающей Ollama и настроенной `.env`:

```bash
uv sync --locked
uv run python -m pytest -q
uv run python -m eval.run validate-data
uv run python -m eval.run validate-data --data eval/data/audit.jsonl
AGENT_MODE=loop LLM_MODEL=qwen2.5:7b uv run python -m eval.run agent \
  --data eval/data/regressions.jsonl --output .cache/eval/my-regressions.json
AGENT_MODE=loop LLM_MODEL=qwen2.5:7b uv run python -m eval.run agent \
  --data eval/data/audit.jsonl --output .cache/eval/my-audit.json
AGENT_MODE=loop LLM_MODEL=qwen2.5:7b uv run python -m eval.counterfactual \
  --output .cache/eval/my-counterfactual.json
uv run python -m eval.compare_retrieval --output .cache/eval/my-retrieval-comparison.json
```

Для всего seed-набора:

```bash
AGENT_MODE=loop uv run python -m eval.run agent --output .cache/eval/my-full-agent.json
```

Для оценки сохранённых ответов другой моделью задайте `JUDGE_MODEL`, при необходимости `JUDGE_BASE_URL` и `JUDGE_API_KEY`, затем:

```bash
uv run python -m eval.assess_saved .cache/eval/my-full-agent.json \
  --output .cache/eval/my-judge.json
```

Каждый запуск сохраняйте в новый файл. Для подробных локальных трейсов включите `TRACE_CONTENT=true`; при обычной работе содержимое исключено из логов. На CPU может понадобиться `LLM_HTTP_TIMEOUT=600`. Контекст Ollama в этих опытах — 8192 токена, один одновременный запрос.

## Границы результата

Агентский цикл реализован, но сам по себе не обеспечивает высокое качество. Модель может составить плохой поисковый запрос, преждевременно остановиться или неверно истолковать источник. Нет долговременной памяти, OCR и произвольного выполнения кода. Приоритет источников и бюджет ограничивают исполнение, а не задают ответ.

Следующая проверка качества требует более широкого независимо размеченного набора. Неудачные примеры сохраняются с источниками и версиями промптов; ожидаемые ответы не заменяются ответами агента.

Направление шкалы API сверено с [определением EIA](https://www.eia.gov/dnav/pet/tbldefs/pet_pnp_crq_tbldef2.asp). Неверные выводы модели не используются как эталон.

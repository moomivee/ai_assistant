# Актуальность и выбор веб-поиска

Изменение от 12 ноября 2026 года относится к ветке `review/agent-eval-20261110`.

В пользовательском трейсе вопрос «когда была последняя встреча опек+?» получил
`fresh=false`. После поиска в отчёте EIA от июля 2025 года модель повторила тот же
запрос. Веб-инструмент не вызывался; исследовательская часть исчерпала бюджет времени.
Наличие в отчёте библиографических ссылок на прошлые встречи не подтверждает,
что одна из них была последней на дату запроса.

## Что изменено

- В промпте планирования и описании поля `Plan.fresh` уточнён смысл актуальности.
  «Последний» без исторического ограничения означает проверку на текущую дату.
  Последний факт внутри конкретного отчёта или прошлого периода — другая задача.
- На шаг выбора действия передаются даты и URL источников. Раньше эти поля
  сохранялись в состоянии запроса, но исключались из сокращённого контекста модели.
- Промпт выбора действия различает недостаток деталей в таблице и недостаток
  актуальности. Приоритет отчётов означает первый поиск в RAG; он не требует
  просматривать все страницы старого документа перед обращением к вебу.
- Генерация ответа получает текущую дату и URL источников. Промпт запрещает
  объявлять историческое событие последним без подтверждения актуальности.

Выбор следующего инструмента остаётся за моделью. Не добавлены маршруты по
ключевым словам, отдельное правило для ОПЕК+ или заготовленный ответ. Набор
доступных действий, запрет веба при `report_only`, защита от повторов и лимиты
времени сохранены. Существующая политика требует попытку веб-поиска, если сама
модель выставила `fresh=true`; это правило существовало до данного изменения.

## Проверка

`tests/test_freshness_context.py` проверяет передачу дат, URL и текущей даты,
сохранение неизвестной даты как `null` и исполнение разных действий, выбранных
моделью после первого поиска. Эти тесты используют подставные ответы модели и
не измеряют качество Qwen.

`eval/data/freshness.jsonl` содержит восемь dev-сценариев: исходный сбой,
переформулировки, историческое ограничение, запрос только по отчёту, статические
свойства нефти, текущая котировка и чистый расчёт. Это регрессионный набор,
а не независимый test-набор. Он не содержит заранее заданной даты последней встречи.

Из корня проекта с настроенным OpenAI-совместимым LLM-клиентом:

```bash
uv run python -m eval.run validate-data --data eval/data/freshness.jsonl
uv run python -m eval.run routing --data eval/data/freshness.jsonl
uv run python -m eval.run agent --data eval/data/freshness.jsonl
```

`routing` проверяет реальную модель с контролируемыми инструментами. Он не
вызывает Tavily и не оценивает достоверность ответа. `agent` выполняет настоящие
поиски и расчёты; для свободного веб-поиска нужен `TAVILY_API_KEY`.
Результаты сохраняются в `.cache/eval/` с новым именем для каждого запуска.
Смотреть нужно не только `plan_fields_correct`, но и `tool_policy_pass`,
`duplicate_actions`, остановки по бюджету и сам ответ со ссылками. Для актуального
события проверить тип встречи, дату её проведения и дату источника вручную.

В Docker-образ не включена папка `eval`. Для прогона из уже работающего контейнера
её можно подключить только на время команды (выполнять из корня проекта):

```bash
docker compose -f compose.yaml -f compose.local.yaml run --rm --no-deps \
  -v "$PWD/eval:/app/eval:ro" analyst \
  python -m eval.run routing --data eval/data/freshness.jsonl
```

Заменить `routing` на `agent` для настоящего поиска. Если нужны сохранённые
результаты на ноутбуке, подключить также каталог `.cache/eval` отдельным томом.

## Ограничения

Промпты помогают модели принять решение, но не гарантируют его. Веб-результат
может отсутствовать, иметь неверно распознанную дату или не проходить фильтры.
Текущая реализация свежего поиска ограничивает публикации параметром
`NEWS_MAX_DAYS` (по умолчанию 30); последнее событие иногда бывает старше этого
окна. Этот фильтр данным изменением не расширяется. Бюджет времени и скорость
локального Qwen также могут ограничить число попыток.

При `PROMPT_SOURCE=langfuse` используются опубликованные версии промптов.
Для проверки файлов этой ветки установить `PROMPT_SOURCE=local` и пересоздать
контейнер либо опубликовать новые версии в Langfuse с нужной меткой.

Инструкция [Tavily agent setup](https://tavily.com/agent-setup/SKILL.md) описывает
подключение сервиса. В проекте уже используется REST API Tavily. Установка CLI
для разработчика сама по себе не изменяет промпты локального Qwen и не обучает
его выбирать `web_search`.

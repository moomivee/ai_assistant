# Тестовый интерфейс

Главная страница приложения теперь предназначена для проверки агента. Слева
показаны ответ, его источники и расчёт; справа — краткий ход запроса. На узком
экране блоки идут друг за другом. График цен по-прежнему открывается по требованию.

## Что показывает стенд

| Блок | Откуда берутся данные |
|---|---|
| Как понят запрос | Проверенный `Plan`: намерение, поисковый запрос, ограничения и параметры прогноза |
| Шаги | `decisions` и результаты исполнения, связанные по номеру решения |
| Цель по плану | Краткое поле `purpose`, которое сформировала модель при выборе действия |
| Аргументы | Фактические параметры, переданные исполнителю инструмента |
| Результат шага | Число найденных фрагментов, их ID, сведения о расчёте, замечания или ошибка |
| Отклонённые действия | Попытки, которые не исполнились: например, повтор одинакового запроса |
| Найденные фрагменты | Источники, полученные агентом, включая не использованные в итоговом ответе |
| Состояние и завершение | Статус ответа, лимит шагов, недоступность модели и замечание проверки |
| Trace ID и JSON | Идентификатор для сопоставления с логами и скачивание ответа API |

Это наблюдаемые данные исполнения и пояснения, явно переданные моделью.
Стенд не восстанавливает скрытые рассуждения. «Цель по плану» объясняет заявленное
назначение действия, но не доказывает, что оно было полезным или что ответ верен.
Статус `ok` означает прохождение реализованных проверок, а не экспертную оценку.

## Как пользоваться

1. Запустить приложение [обычным способом](Setup.md) и открыть `http://localhost:8000`.
2. Задать вопрос. Ход запроса появится вместе с ответом после завершения обработки;
   трансляция шагов в реальном времени не реализована.
3. Раскрыть «Как понят запрос» и проверить параметры. Для конкретного шага открыть
   «Аргументы и результат шага».
4. Сопоставить «Найденные фрагменты» с «Источниками ответа»: нужный документ мог
   попасть в поиск, но не попасть в итоговый текст.
5. При ошибке скопировать Trace ID и скачать JSON из блока «Полный ответ API».

Отдельно включать `TRACE_CONTENT=true` для этого экрана не нужно: краткая
диагностика приходит непосредственно в `AgentResponse.diagnostics`. Эта настройка
по-прежнему управляет сохранением содержимого в JSONL/Langfuse. [Подробные трейсы](Observability.md)
нужны, чтобы посмотреть отдельные LLM-вызовы, версии промптов и расход токенов.

## Границы диагностики

- Время запроса измеряется браузером и включает ожидание HTTP-ответа; время шага —
  время исполнения инструмента. Для отклонённого действия время не придумывается.
- Число решений включает отклонённые попытки и переход к ответу; число выполненных
  вызовов считается отдельно. Два одинаковых названия инструмента не используются
  для угадывания связи между решением и исполнением.
- В диагностике показаны первые 4000 символов каждого найденного фрагмента.
  Обрезка явно отмечается; в ответе сохраняется ссылка на исходный документ.
- Прежний workflow и сохранённые старые ответы могут не содержать `diagnostics`.
  Для них показываются доступные события и предупреждение о неполной диагностике.
- JSON содержит ответ этого запроса, а не все внутренние spans Langfuse.
- Добавление экрана не меняет промпты и наблюдения, передаваемые модели. Новый
  замер качества Qwen в рамках этой доработки не выполнялся.

## Архив и проверки

Пользовательский интерфейс сохранён без изменений в
[archive/user-interface-2026-11-11](../archive/user-interface-2026-11-11/README.md).
В архиве есть контрольные суммы и команды восстановления.

Тесты `tests/test_trace_diagnostics.py` проверяют связь решений и исполнения,
отличие ошибки от отклонения, корректность ID источников, отсутствие выдуманного
времени, совместимость старого API и неизменность контекста LLM.

Браузерная проверка использует контролируемые ответы, включая ошибки, пустые
результаты, повторы и ответ прежней версии. Это проверка интерфейса, не eval модели:

```bash
uv run --with playwright python -m playwright install chromium
uv run --with playwright python tools/check_trace_ui.py
```

Результаты браузерной проверки и снимки сохраняются в `docs/assets/trace-workbench-*`.

# Подключение GigaChat API для физлиц

Инструкция для третьей ветки `review/v3-knowledge-gigachat-20261114` и личного проекта GigaChat API. Основная и вторая ветки используют прежнюю конфигурацию. Адаптер прямого API подготовлен; качество живых ответов GigaChat ещё не измерено.

## Получить ключ

1. Открыть созданный проект GigaChat API, например «ИИ агент», в личном пространстве Studio.
2. Выбрать **Настройки API**, затем **Получить ключ** в блоке данных авторизации.
3. Скопировать **Authorization Key** и сохранить его: кабинет показывает значение один раз.
4. Записать значение в локальный `.env` как `GIGACHAT_CREDENTIALS`. Не добавлять `Basic`, кавычки интерфейса или угловые скобки из примера команды.

`GIGACHAT_API_PERS` — scope личного доступа. Authorization Key нужен для получения access token, действующего 30 минут. Пример `curl ... /oauth` обменивает готовый ключ на токен, а не создаёт сам ключ. Приложение получает и обновляет токен самостоятельно; копировать access token в `.env` не нужно.

Название проекта в кабинете не является именем модели. Доступные модели определяются аккаунтом и показываются командой `check-llm`.

## Отдельная папка третьей версии на Mac

Если папка третьей версии ещё не создана:

```bash
cd ~/Projects
git clone --branch review/v3-knowledge-gigachat-20261114 https://github.com/moomivee/ai_assistant.git ai_assistant_ver_3
cd ai_assistant_ver_3
if [ ! -f .env ]; then cp .env.example .env; fi
nano .env
```

Нужные значения:

```env
LLM_PROVIDER=gigachat
GIGACHAT_CREDENTIALS=ВСТАВИТЬ_AUTHORIZATION_KEY
GIGACHAT_SCOPE=GIGACHAT_API_PERS
GIGACHAT_BASE_URL=https://api.giga.chat/v1
GIGACHAT_MODEL=GigaChat-2
PORT=8003
```

`GigaChat-2` — кандидат для первого запуска. Если его нет в списке моделей аккаунта, выбрать доступный ID. Не нужно покупать конкретную модель до проверки доступности. Tavily настраивается независимо через `TAVILY_API_KEY`.

Сохранить в nano: Control+O, Enter; выйти: Control+X. `.env` исключён из Git. Не присылайте ключ, access token или полный вывод `docker compose config`: последний может раскрыть секреты.

## Docker

```bash
docker compose -f compose.yaml -f compose.gigachat.yaml up --build -d
docker compose -f compose.yaml -f compose.gigachat.yaml exec analyst python -m src.cli check-llm
```

Команда проверки выполняет авторизацию и GET списка моделей, выводит только провайдера, выбранную модель и доступные ID. Она не отправляет вопрос модели и не подтверждает поддержку наших схем или качество ответов.

После успешной проверки открыть http://localhost:8003. Не добавлять `compose.local.yaml`: этот файл запускает Ollama. Папки `ai_assistant`, `ai_assistant_ver_2` и `ai_assistant_ver_3` по умолчанию образуют разные Compose-проекты; не задавать им одинаковый `COMPOSE_PROJECT_NAME`/`-p`.

### Проверка сертификатов

TLS-проверка включена. Если возникает ошибка доверия сертификату, получить доверенные сертификаты по [официальной инструкции](https://developers.sber.ru/docs/ru/gigachat/certificates) и сохранить PEM bundle локально, например `certs/gigachat-ca.pem`.

Для Docker указать в `.env`:

```env
GIGACHAT_CA_BUNDLE=/app/certs/gigachat-ca.pem
```

`compose.gigachat.yaml` монтирует локальный каталог `certs` в `/app/certs` только для чтения. Файл должен существовать; переменная не скачивает сертификат. Дополнительный bundle добавляется к системным доверенным корням. Проверку TLS не отключать.

### Смена ключа или модели

```bash
cd ~/Projects/ai_assistant_ver_3
nano .env
docker compose -f compose.yaml -f compose.gigachat.yaml up -d --force-recreate --no-deps analyst
docker compose -f compose.yaml -f compose.gigachat.yaml exec analyst python -m src.cli check-llm
```

Пересборка образа после изменения ключа не нужна. При изменении кода требуется запуск с `--build`.

## Без Docker

В той же папке с заполненным `.env`, при установленном uv:

```bash
uv sync --locked
uv run python -m src.cli check-llm
uv run python -m src.cli prepare
uv run uvicorn src.api:app --host 127.0.0.1 --port 8003 --workers 1
```

Если используется дополнительный CA bundle, задать в `.env` абсолютный путь на Mac вместо `/app/certs/...`. Ollama для этого запуска не нужна. `prepare` загружает эмбеддер и строит RAG, но не вызывает GigaChat.

## Первая живая проверка

После настройки выполнить один запрос:

```bash
curl -sS http://127.0.0.1:8003/api/ask \
  -H 'Content-Type: application/json' \
  -d '{"question":"Чем отличаются Urals и ESPO по плотности и содержанию серы? Только по загруженным отчётам."}'
```

Проверить ответ по процитированным страницам, модель в поле `mode`, вызовы инструментов, статус и трейс. Затем отдельно проверить прогноз и актуальный веб-вопрос. Один успешный запрос не заменяет eval.

Для личного API действует ограничение параллельных обращений. Адаптер сериализует вызовы внутри одного процесса. Запускать один worker; не запускать одновременно несколько серверов/CLI/eval с одним аккаунтом. Лимит между разными процессами и контейнерами локальная блокировка не координирует.

## Что делает адаптер

- Нативные OAuth и запросы GigaChat через существующий HTTP-клиент httpx; дополнительный SDK не требуется.
- Схема в `response_format.schema`, строгий режим и последующая Pydantic-валидация. Это отличается от OpenAI wire-format.
- Обновление токена по сроку действия; после HTTP 401 — одна повторная авторизация и одна повторная отправка, без бесконечного цикла.
- Различение отсутствующего ключа, ошибок доступа/квоты, отказа модели и неверного ответа по схеме. Нет подмены ответа локальными правилами или скрытого перехода на Qwen.
- В трейсах — провайдер, модель, схема, время и доступная статистика токенов. Ключи и access token не записываются.

Бюджет выполнения кооперативный: ограничивает ожидание блокировки и исходящие операции, проверяется между ними. HTTP-таймаут не является гарантией точного общего времени ответа.

`/health` означает, что HTTP-сервис жив. `/api/status` показывает конфигурацию, не проверяя ключ. `/ready` проверяет готовность индекса, авторизацию и наличие выбранной модели; это не генерация по схеме.

При `PROMPT_SOURCE=langfuse` используются опубликованные промпты. Первый smoke проще провести с `PROMPT_SOURCE=local`, чтобы версия промптов совпадала с кодом ветки.

## Проверки и границы результата

Тесты с MockTransport проверяют формат запросов, токены, ошибки, валидацию и бюджеты без реального ключа. Их успех не является измерением GigaChat. Живой smoke, качество структурированной генерации на выбранной модели и сравнение с Qwen требуют доступа пользователя и сохраняются отдельно.

При подготовке адаптера локально прошли 178 тестов Python, `ruff check`, `ruff format --check` и `eval.run validate-data` (100 вопросов, 40 с эталонными фрагментами). Compose-файлы проверены как YAML; сборка и запуск Docker в этом локальном окружении не выполнялись. Эти результаты не относятся к живому eval GigaChat.

Смена генеративной модели не меняет эмбеддер: пока остаётся прежний MiniLM/FAISS, чтобы сравнение моделей было осмысленным. В облачный API отправляются вопрос и используемый контекст. OCR, загрузка документов через UI и память Ouroboros ещё не реализованы в этом этапе.

Для независимого OpenAI-совместимого оценщика задаются все три значения `JUDGE_API_KEY`, `JUDGE_BASE_URL`, `JUDGE_MODEL`. Если они не заданы, используется основной провайдер; такая оценка той же моделью не считается независимой.

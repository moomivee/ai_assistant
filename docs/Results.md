# Результаты исходного workflow

Этот срез сохранён для сравнения с `AGENT_MODE=workflow`. Изменения нового агентского цикла и свежие измерения описаны в [аудите](AgentAudit.md).

Состояние проверок на 10 ноября 2026 года. Это учебный прототип: автоматические проверки кода и качество ответов оцениваются отдельно.

## Что проверено

- `uv sync --locked` завершён успешно.
- `ruff check` и `ruff format --check`: без ошибок.
- `pytest`: **80 passed**. Проверяются ветвления LangGraph, реальный ToolRegistry Ouroboros и расчёт, OpenAI SDK с HTTP-фикстурой, фильтры источников, API, eval UI, trace-кандидаты и native Langfuse export в локальный OTLP-приёмник. Дополнительно проверяются случаи из пользовательских ответов: параметры прогноза, лишний веб-контекст, процентные диапазоны, проверка цитат, индексы проверки и ограниченная коррекция ответа.
- `validate-data`: **100 вопросов, 40 retrieval-вопросов, 83 группы, 115 чанков**. Все эталонные цитаты присутствуют в PDF-чанках.
- Реально выполнен retrieval для двух ONNX-моделей, двух вариантов запроса и всех 40 размеченных вопросов (160 поисковых запросов).

## Реальный прогон Qwen: что получилось

Обе модели проверены на одних и тех же трёх пользовательских регрессиях, документах и промптах, с контекстом 8192 и ожиданием LLM до 600 секунд. Код: `ff9eadeb13f474a56c50bb1f8780ad0f21fd9df7`. [Запуск с ответами и трейсами](https://github.com/moomivee/ai_assistant/actions/runs/42802420335).

| Сценарий | Qwen2.5:3b | Qwen2.5:7b |
|---|---|---|
| Brent на 3 месяца, только расчёт | Пройден | Пройден |
| Обычный прогноз Brent без дополнительных тем | Пройден | Пройден |
| Сравнение Urals и ESPO по плотности и сере | Не пройден | Не пройден |
| Всего | **2 из 3** | **2 из 3** |

В обоих сценариях прогноза выполнен маршрут `report_search → price_forecast`; результат содержит расчёт, интервал, дату истории и сравнение ошибок. Лишний веб-поиск и сообщения об отсутствии уже рассчитанного прогноза не появились.

На сравнении сортов 3B находит правильные числа, но меняет названия и делает неверные выводы: путает направление шкалы API и выводит меньшую плотность из меньшей сернистости. Проверка той же моделью эти ошибки пропускает. У 7B другая проблема: модель соединяет несмежные строки таблицы в якобы дословную цитату. Проверка цитаты отклоняет её, и полный ответ не формируется. Более крупная модель сама по себе не устранила сбой.

## Что исправлено и что осталось

Реализованы проверка ответа по источникам, одна попытка коррекции по проверенным цитатам, ограничение индексов проверки через JSON Schema, корректная обработка числовых диапазонов и пропуск повторной генерации после пустого веб-поиска. Сначала формируются факты, затем оценивается полнота; свободные заявления модели об отсутствии данных не выводятся пользователю.

После сохранения переносов строк повторены 160 retrieval-запросов. Ранги и метрики не изменились; [сравнение](../eval/results/retrieval-preserve-lines-2026-11-10.json). Это сохранение измеренного качества поиска, а не его улучшение.

**Открытое ограничение:** надёжное сравнение табличных данных и смысловая проверка ответа ещё требуют доработки. В найденном PDF нужная таблица есть; сбой возникает при её использовании моделью. Следующий шаг — адресовать фрагменты таблицы устойчивыми идентификаторами, формировать цитаты из исходного текста кодом и оценивать интерпретации независимо от отвечающей модели. Эти изменения в текущую версию не входят.

[Проверки кода, Docker и API](https://github.com/moomivee/ai_assistant/actions/runs/42802420561) завершились успешно. Неуспешный live eval сохранён как есть; ожидания тестов не ослаблялись.

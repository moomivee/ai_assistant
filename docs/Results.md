# Результаты текущей итерации

Это результаты восстановленной версии кода.

## Что проверено

- `uv sync --locked` завершён успешно.
- `ruff check` и `ruff format --check`: без ошибок.
- `pytest`: **26 passed**. Проверяются ветвления LangGraph, реальный ToolRegistry Ouroboros и расчёт, OpenAI SDK с HTTP-фикстурой, фильтры источников, API, eval UI, trace-кандидаты и native Langfuse export в локальный OTLP-приёмник.
- `validate-data`: **100 вопросов, 40 retrieval-вопросов, 83 группы, 115 чанков**. Все эталонные цитаты присутствуют в PDF-чанках.
- Реально выполнен retrieval для двух ONNX-моделей, двух вариантов запроса и всех 40 размеченных вопросов (160 поисковых запросов).

По dev предварительно выбран `minilm-multi`: он чаще находит нужный контекст в top-5 и поднимает его выше. На test E5 лучше по hit@5, а MiniLM — лишь немного по MRR. 

Полный пользовательский вопрос включает указание «только отчёты»; оно не является содержательным запросом к документу. Его результаты:

| Эмбеддер | hit@1 | hit@5 | MRR@10 |
|---|---:|---:|---:|
| e5-small | 0.200 | 0.400 | 0.279 |
| minilm-multi | 0.250 | 0.550 | 0.385 |

Числа показывают заметные пробелы RAG. Корпус мал, русские вопросы сопоставляются в основном с английским отчётом, таблицы теряют структуру при извлечении, токенизатор MiniLM ограничен 128 токенами.
